## effect 보존

입력은 최근 매핑에 사용한 `claims_all_y_final.json`과 동일한 SHA-256의 원본임. 영상 535개, 제품 항목 1,302개, Claim 8,728개를 모두 포함함. 모든 Claim의 필드와 값, 순서를 원본과 비교했으며 **effect 8,728개(값이 있는 2,438개 포함)를 null까지 그대로 보존함.** 원본의 나머지 Claim 필드도 삭제하거나 재분류하지 않았음.

확정 제품의 `DB`에는 `QUANTITY`, `COMPOSITION`, `CERTIFICATION`, **`EFFECT`** 네 묶음이 모두 있음. 스칼라 결측은 `""`, 원료 배열 결측은 `[]`임. `MAIN_FNCTN`은 기존 DB `main_functionality`의 원문이며 `EFFECT`와 `CERTIFICATION`에 각각 포함됨.

## confirmed 조건

출력 MD대로 **confirmed인 항목만 DB 객체를 제공**함. `unresolved`, `not_found`이면 `DB: null`, `method/matched_name/matched_company: null`임. 기존에 후보 그룹을 하나 선택한 기록도 확정 상태가 아니면 DB를 넣지 않음. Claim 제조원 보완 결과도 기존 검토 상태를 자동 승격하지 않음.

- confirmed: 89개 영상별 제품 항목
- unresolved: 972개
- not_found: 241개
- 합계: 1,302개

위 집계는 영상별 제품 항목이며 중복 제거 제품 501개 기준 매핑률과 다른 집계임. 예전 전처리에서 브랜드 결측으로 제외한 제품 항목 15개도 전달 JSON에는 원본 그대로 보존하되 확정 DB 연결에는 다시 포함하지 않았음. 원래 참조가 없는 Claim 290개도 삭제하거나 다른 제품에 임의 배정하지 않고 영상의 claims 안에 보존함.

`match.candidates`는 동일한 정규화 제품명의 DB 원본 행 수임. 확정 항목은 선택된 DB 이름, 미확정 항목은 입력 이름의 전체·브랜드 분리/결합 이름으로 집계함. 오타 검색의 모든 후보 수와 혼동하지 않도록 전체 후보와 그룹 구분 기록은 별도 매핑 감사 파일에 남김.
