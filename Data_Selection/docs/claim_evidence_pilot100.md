# Claim 100개 제품 식별 및 Evidence 순위 시험

입력: `claims_all.json`의 영상 216개·Claim 3,400개. 사용자 제공 `Clam ↔ Evidence 번뇌 찐막.pdf`의 제품 식별·검색 단계에 따라 처리한다. 원본 JSON 및 SQLite DB는 변경하지 않는다.

## 표본

기본값은 **Claim 100개**다. seed 42로 영상을 섞고 영상마다 Claim을 순환 추출해 첫 영상의 Claim들만으로 표본이 채워지지 않게 한다. 이번 입력에서는 영상 100개에서 Claim 하나씩 선정된다. 영상 100개의 모든 Claim을 처리하는 옵션은 `--video-limit 100`이며 별도 출력 폴더를 사용한다.

제품 식별에는 선택한 Claim뿐 아니라 해당 영상에서 같은 product_ref의 전체 Claim에 있는 제조원 표기도 참고한다. 서로 다른 제품의 문맥을 섞지 않는다. 브랜드는 제조사로 사용하지 않는다.

## 제품 식별

1. 품목제조신고번호·전체 이름 정확 일치를 확인하고 제조사·신고번호 충돌이 있으면 연결하지 않는다.
2. 정확 일치가 없으면 단어 경계를 보존한 온전한 구절을 포함하는 모든 제품을 검색한 다음 제조사를 비교한다. 유일한 후보만 연결한다.
3. 구절 후보도 없으면 확인된 동일 제조사의 제품 전체 이름에 Damerau–Levenshtein 점수 80 이상을 적용한다. 통과 후보가 정확히 하나여야 한다.

NFC·대소문자·공백과 법인 표기, 제2공장/2공장의 표기 차이만 정리한다. 서흥과 서흥헬스케어 같은 회사명 차이를 임의로 합치거나 공장명을 지우지 않는다. 숫자·단위·제품 기호는 보존한다. PDF의 95.6% 문구를 성능 보장으로 재사용하지 않는다.

## 검색 및 점수

제품을 식별하면 products의 기능성·규격·섭취법·주의사항 등 원문을 행 단위로 분리한다. 원본 컬럼과 문자 위치를 보존한다. 긴 행은 겹치는 창으로 나누며 모델 입력 최대 길이는 512토큰이다.

입력에서 관찰된 원료와 식별한 제품의 기능성 원문에 나타난 원료명을 ingredients와 비교하고, 해당 원료의 실제 evidence 행을 조회한다. 이름에 인정번호와 영문 상표 괄호가 붙은 경우 기본명도 후보 검색에 사용하므로 원료 형태나 인정번호가 확정됐다는 뜻은 아니다. 제품–원료 연결 테이블이 없으므로 원료 참고자료로 구분하고 실제 함유 사실로 취급하지 않는다. 일반 원료명과 특정 인정 원료의 차이는 후속 검토 대상이다.

이번 시험은 제품·원료로 후보 범위를 제한하므로 PDF의 **“Evidence가 적으면 전체를 직접 재정렬”** 방식을 사용한다. BGE-M3 임베딩으로 후보를 미리 잘라내지 않는다. BAAI/bge-reranker-v2-m3가 Claim·필요 문맥과 각 후보 원문·대상·유형을 함께 읽고 점수를 계산한다. 모델 revision은 실행 시 고정해 기록한다.

모든 후보의 **원시 logit과 sigmoid(logit)**를 보존하고 점수 내림차순으로 정렬한다. 이는 관련성 점수이며 참·거짓 확률이나 코사인 유사도가 아니다. PDF에 따라 별도 점수 임계값은 적용하지 않는다. 이전 NEM 사례의 TF-IDF 0.10과 서로 다른 점수다.

## 산출물

기본 폴더: `data/processed/claim_evidence_pilot100/`

- `prepared.json`: 선택된 Claim·제품 식별 결과·원문 출처와 전체 후보.
- `claim_evidence_ranked.json`: 전체 후보 순위와 기본 Top-3, 제품/원료 구분, 점수, 출처. 후보 없음은 `no_linkable_evidence` 및 빈 목록. 최종 verdict는 null.
- `summary.json`: 후보 수 분포 및 Top-1/3/5/10으로 자를 때 연결 개수 비교.
- `reranker_scores.sqlite`: 모델 revision과 입력쌍 기준 점수 캐시. 재실행 시 계산한 쌍은 건너뛴다.
- `progress.json`: 계산 진행 상황. 모델 파일은 `.tools/huggingface/`에 저장한다.

후보 수 분포와 점수만으로 최적 K를 확정할 수 없다. 각 순위의 원문을 사람이 관련/무관으로 표기해야 K별 누락·불필요 근거를 비교할 수 있다. 낮은 점수 후보를 Top-3에 포함했다고 검증 가능한 자료로 확정하지 않는다. 복합 Claim의 세부 항목별 근거 충분성은 아직 미판정으로 표시한다.

## 실행

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-reranking.txt
.\.venv\Scripts\python.exe -u -X utf8 scripts/run_claim_evidence_pilot.py --input "C:\Users\박이정\Documents\카카오톡 받은 파일\claims_all.json"
```

후보 준비만 실행하려면 `--prepare-only`를 추가한다. 실행이 중단되면 같은 명령으로 재개한다. 최초 모델 다운로드는 약 2.27GB이며 CPU에서는 점수 계산에 시간이 걸릴 수 있다. 외부 유료 API나 자동 최종 판정은 사용하지 않는다.

모델 구현 근거: [공식 모델 카드](https://huggingface.co/BAAI/bge-reranker-v2-m3), [공식 BGE 재정렬 설명](https://bge-model.com/bge/bge_reranker_v2.html).
