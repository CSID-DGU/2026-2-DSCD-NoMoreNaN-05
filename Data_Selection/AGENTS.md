# 프로젝트 작업 지침

## 합의된 인터페이스와 기준을 임의로 변경하지 않기

- 사용자와 팀이 합의한 JSON 필드명, 상태값, 데이터 구조, 매핑 기준, 판정 기준을 사용자 승인 없이 변경하지 않는다.
- 오류 수정이나 매핑률 개선을 이유로도 새로운 상태값을 추가하거나 기존 상태값의 의미를 바꾸지 않는다.
- `confirmed / unresolved / not_found`를 `matched` 등 다른 상태 체계로 임의 교체하지 않는다.
- 후보 검색 성공, 제품 하나 선택, 제품 동일성 확정, 근거 연결, Claim 판정을 구분한다. 매핑률을 높이려고 후보를 확정으로 간주하거나 집계 기준을 바꾸지 않는다.
- 제품 매칭 상태와 Claim 판정 라벨은 서로 다른 값이다. 어느 쪽이든 합의된 의미와 구조를 유지한다.
- 변경이 필요하면 기존 형식과의 차이, 변경 이유, 수신 코드와 집계에 미치는 영향을 먼저 설명하고 사용자의 명시적 승인을 받은 뒤 반영한다.
- README 작성이나 새 버전 파일 생성만으로 변경 승인을 대신하지 않는다. 사용자에게 알리지 않은 새 형식을 팀원 전달용으로 지정하지 않는다.
- 오류 수정은 우선 기존 합의와 호환되는 범위에서 진행한다. 합의가 불명확하면 관련 자료를 확인하고, 인터페이스 변경이 필요한 부분만 사용자에게 확인한다.
- 변경하지 않은 사항을 구현 완료라고 설명하거나, 수신 측 코드에서 확인하지 않은 호환성을 보장하지 않는다.

이 지침은 사용자의 2026-11-04 명시적 요청에 따른 프로젝트의 지속 작업 규칙이다.
